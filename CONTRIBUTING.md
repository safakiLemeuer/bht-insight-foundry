# Contributing

## Required workflow

1. Open or select a GitHub issue.
2. Create a small branch such as `feature/001-bootstrap-repository`.
3. Make one logical, reviewable change.
4. Add or update tests and documentation.
5. Open a pull request using the repository template.
6. Resolve all review comments and required checks.
7. Squash merge into `main`.

## Commit style

Use Conventional Commits:

- `feat:` new capability
- `fix:` defect correction
- `docs:` documentation only
- `test:` tests
- `refactor:` internal code improvement
- `perf:` performance improvement
- `security:` security improvement
- `ci:` automation
- `chore:` maintenance

## Documentation rule

Important changes must explain:

- Business purpose
- Architecture impact
- Data flow
- Control flow
- Security impact
- Performance and cost impact
- Test evidence
- Assumptions and limitations
